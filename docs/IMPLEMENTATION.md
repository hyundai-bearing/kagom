## 디자인에 없던 값 (가정)

- **MNT-02 후속 수정 (2026-11-10, 사용자 승인)**: Pleos 누적 주행거리 기준 10,000 km마다 점검한다. 12개월 경과만으로 완료를 열지 않는다. 1만 km 완료 후 2만 km 미만에서는 체크리스트 대신 완료 내역·다음 점검까지 남은 거리를 표시한다. 신호 누락·비정상 값에서는 완료를 막고 확인 불가를 표시한다. 컨트롤러도 최신 거리·차종·필수 체크를 재검증하므로 연타로 다음 회차가 완료되지 않는다. 놓친 회차는 현재 도달한 구간을 한 번만 완료하며 과거 회차를 연속 처리하지 않는다. 기존 저장 키와 완료 기록은 유지한다.
- **전기차 점검 항목**: 연료/SOC 신호로 판별한 EV에는 타이어 공기압·마모, 전조등·방향지시등·브레이크등, 와이퍼·워셔액을 표시한다. 가솔린·HEV 문구와 저장 키는 유지하고 EV 체크는 별도 키를 쓴다. EV에는 엔진오일 교체 카드를 표시하지 않는다. 디버그 `--ez demo_ev true|false`로 실제 컨트롤러를 전환할 수 있다.

- **POP-02~05 승인 사항 (2026-11-10)**: Full/Split Figma 원본(POP-02 `63:3228`, `7:2514`, `64:3673`, `64:3841`; POP-03 `7:2528`, `64:3979`; POP-04 `7:2542`, `64:4135`; POP-05 `7:2433`, `7:2471`) 기준. 실제 Pleos 창은 넓을 때 1682×1210, 좁을 때 841×1210이므로 비율이 다르다. 보상·레벨업은 높이가 부족할 때 본문을 스크롤하고 버튼은 고정한다. 정비 Split 시트는 상단 최소 128 디자인 px을 남기고 전체 내용을 스크롤한다. 추가 축소는 하지 않는다.
- **팝업 상태·닫기**: 열기 560ms / 빛 걷힘 520ms / EXP 900ms 유지. 열기 수락 즉시 `opened`를 저장해 주행·Activity 재생성 후 공개 단계에서 재개한다. POP-02~04는 버튼으로만 종료하며 바깥 터치·뒤로가기는 소비한다. POP-05는 바깥 터치·뒤로가기로 닫고 끌어내리기는 지원하지 않는다. 정비 시트가 열린 동안 보상 큐는 표시·소비하지 않는다.
- **보상 표현**: 캐릭터는 현재 스킨·착장을 유지한다(신규 보상 미리 착용 안 함). 쇼케이스에는 기존 `KagomRenders.thumbPath` 이미지를 쓰고 없을 때만 Mark를 쓴다. 랜드마크명·방문일·보상·EXP·방문 횟수는 해당 큐 데이터로 표시하며 정동진/커피거리/주문진항에 기존 해돋이/커피/배 글리프를 사용한다. POP-04는 레벨 숫자·포인트 칩 중심의 어두운 카드이며 기존 통계·추가 문구를 넣지 않는다. 실제 포인트 API 연동은 추가하지 않았다.
- **Figma 정적 에셋**: `assets/popups/`의 지형(`63:3464`), 레벨업 광선(`225:4595`, `225:4650`)·월계관(`225:4624`, `225:4679`)은 Figma MCP Bridge 0.0.25 `get_screenshot` PNG scale=2, clip=true 내보내기다. 생성된 `assets/kagom` 및 `assets/regions`는 변경하지 않는다.
- **팝업 시연**: 디버그 패널의 “팝업 미리보기” 또는 `--es demo_popup reward|reveal|landmark:LM-GN-01|landmark:LM-GN-02|landmark:LM-GN-03|level|maintenance|maintenance-ev|maintenance-done|off`. `Examples.popups`의 EX- 데이터만 사용하고 프로필·아이템·포인트·정비 기록을 저장하지 않는다. 기어 신호는 실제 앱과 같은 `--es demo_gear P|D`를 따른다. 프리뷰의 장착/정비소 버튼은 외부 변경을 실행하지 않으며 실제 저장 동작 검증과 구분한다. 검증 절차·스크린샷은 `docs/verification/popups/README.md` 참고.

- **티어 기준 EXP**: 0 / 400 / 900 / 1,350 (디자인의 "티어 1→2 = 400"에 맞추고, 보상 EXP 총합 1,350으로 티어 4까지). 승급마다 블루멤버스 +1,000 P.
- **랜드마크 좌표·반경**: 정동진·안목 커피거리·주문진항 근처, 반경 400 m. 같은 곳은 하루 1회만 방문으로 센다.
- **"랜드마크 3곳 방문"(QST-03)**은 서로 다른 장소 수, **"랜드마크 10회 방문"(QST-04)**은 전체 방문 수로 셌다 (Figma 문구 "3곳" + spec "10회").
- **아이템 Mark 글자**: 커피콩 모자 C, 안전 조끼 V, 보드숏 S (Figma에 없던 것만).
- **엔진 종류**: 연료 신호 없고 배터리만 있으면 EV, 둘 다면 하이브리드, 아니면 가솔린.
- **"나중에"(언박싱)**: 이번 정차 동안만 넘기고, 기어가 P를 벗어났다 돌아오거나 앱을 다시 켜면 다시 나온다.

## 랜드마크 지도 (SCR-05)

- 전국 지도에서 시·도를 선택하면 그 시·도의 시·군 지도, 시·군을 선택하면 구획 지도가 열린다. 지도와 목록에서 동일하게 선택할 수 있다. 상단 경로, 뒤로 가기, 지도에서 오므리기로 이전 단계로 돌아간다.
- Full에서는 지도 오른쪽, Split에서는 지도 아래에 지역별 해금 목록을 표시한다. 진행도는 실제 등록된 랜드마크와 방문 기록을 집계한다. 미해금은 회색, 일부 해금은 연두, 모두 해금은 초록, 선택된 구획은 점선 테두리다.
- 강릉의 1읍·7면과 시내 13개 동을 9개 구획으로 표시한다. 선택한 구획의 핀은 기존 랜드마크 위경도를 지도 경계와 같은 방식으로 투영한다. 정차 중에는 핀이나 목록에서 보상 상세를 열 수 있다. 랜드마크가 없는 구획은 준비 중으로 표시한다.
- 전국·시·군 경계는 기존 `assets/regions/korea_map.txt`를 사용한다. 원본 © OpenStreetMap contributors (ODbL). 생성 순서는 `fetch_korea.py` → `fetch_coast.py` → `build_korea.py`다.
- 강릉 경계는 [통계청 통계지리정보서비스(SGIS)](https://sgis.kostat.go.kr)의 공공누리 제1유형 경계를 가공한 [vuski/admdongkor 2026-10-01 데이터](https://github.com/vuski/admdongkor/tree/d5d5a821c8de6cc337d47eeca604d7af76271c9b/ver20261001)를 사용한다. 가공 데이터는 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)이다. `python tools/regions/build_gangneung.py HangJeongDong_ver20261001.geojson`으로 강릉 경계를 추출하고 단순화해 `gangneung_districts.txt`를 다시 만든다.

## 캐릭터·치장 3D 렌더 (`tools/closet3d/build_closet.py`)

곰 모델(`tools/closet3d/source/pebble_bear.glb`)과 스킨 텍스처(`tools/closet3d/source/skins/`)에 맞춰 Blender에서 치장 아이템을 절차적으로 모델링하고, 같은 카메라로 렌더한다.

| 파일 (`assets/kagom/`) | 내용 |
|---|---|
| `base_<P0n>_<표정>.webp` | 스킨 8 × 표정 7 = 56장, 614×965 (Figma pebble 렌더 크기) |
| `item_<ID>.webp` | 착용 레이어 6종. 곰은 그림자만 받는 투명 처리 → 기본 위에 그대로 겹치면 맞는다 |
| `thumb_<ID>.webp` | 아이템 6종 + 칭호 메달 3종 썸네일 320×320 |
| `turn/b_<P0n>_<단>_<nn>.webp`, `turn/i_<ID>_<단>_<nn>.webp` | 돌려보기 프레임 480×754: 고도 3단(약 9°·25°·40°) × 48방향(7.5°) |
| `motion/<동작>/b_<P0n>_<nn>.webp`, `motion/<동작>/i_<ID>_<nn>.webp` | 터치 반응 동작 프레임 640×830 (24 fps): 손 흔들기 38장, 만세 22장, 발 동동 28장 |

카메라는 하나(`Rig`)다. 곰 가운데를 축으로 yaw(조명도 같이 돈다)와 pitch(위에서 내려다보기)만 바꾸고 거리는 같아서, 단을 바꿔도 곰 크기·위치가 튀지 않는다.
base·item은 이 카메라의 0단 2번 프레임(곰 왼쪽으로 15°, `HOME_YAW`)으로 찍는다 → 홈에서 밀기 시작하면 돌려보기 프레임으로 그대로 이어진다.
동작 프레임도 같은 카메라(0단, `HOME_YAW`)인데 팔을 벌리거나 뛰면 화면 밖으로 나가서, 픽셀 크기는 같게 두고 화면만 좌우 80 px·위 76 px 넓혔다 (`MW`, `MH`). 가운데 480×754가 돌려보기 프레임과 픽셀 단위로 겹친다.

표정 = 눈·입 셰이프 키 + 소품. 몸·머리 자세는 그대로 둬서 치장 레이어가 모든 표정에 맞는다.

| 표정 | 눈·입 | 소품 |
|---|---|---|
| 대기 | 기본 미소 | – |
| 배고픔 1 | 큰 눈, 입 벌림 | 작은 침방울 |
| 배고픔 2 | 살짝 졸린 눈, 입 크게 벌림 | 침방울 |
| 배고픔 3 | 처진 눈, 찡그린 입 | 침방울 + 식은땀 |
| 얼룩 | 큰 눈, 일자 입 | 볼·배·팔 기름 얼룩 |
| 피곤함 | 반쯤 감은 눈, 일자 입 | Z Z Z |
| 아픔 | 처진 눈, 찡그린 입 | 열 홍조 + 반창고 + 식은땀 |

**돌려보기** (`KagomTurntable`, `TurnState`, `turnGestures`): 치장 미리보기, SCR-02 결과 화면, 홈.
- 좌우로 밀면 돌고(관성 있음), 위아래로 밀면 고도 단이 바뀐다 (아래로 72dp 밀 때마다 한 단 위에서 내려다본다 → 머리 위 아이템 확인).
- 프레임 사이 각도에서는 양옆 방향 두 장 × 위아래 단 두 장(최대 네 장)을 각도 비율대로 섞어 그린다 (`TurnImage`, 미리 곱한 알파끼리 더하기라 겹친 곳이 비치지 않음). 예전에는 15°마다 한 장씩 바뀌고 단도 반올림해서 끊겨 보였다.
- 치장·온보딩: 손을 떼면 그 각도에 멈추고 "정면"으로 돌아간다. 홈: 손을 떼고 0.9초 뒤 제자리로 돌아오며 표정 렌더로 바뀐다.
- 프레임마다 몸 + 착용 레이어를 합성해 캐시한다. 지금 각도에서 가까운 프레임부터(같은 단 전부 → 이웃 단 ±3) 만들고 최대 40장(약 58 MB)만 든다. 홈은 처음 밀 때 만들기 시작하고 20초 동안 안 돌리면 내려 둔다.
- 주행 중(gear≠P)에는 정면 고정, 홈은 대기 표정일 때만 돌릴 수 있다 (터치 반응과 같은 조건).

- 아이템: 해돋이 머리띠, 커피콩 모자, 빨간 고무 앞치마, 초보운전 안전 조끼("초보" 배지), 데님 멜빵 반바지, 강릉 서퍼 보드숏.
- 옷은 몸 안쪽 축에서 광선을 쏴 표면을 따라 만든다 (밑단이 수평, 팔·꼬리 자리는 비움).
- 몸 뚫림 방지: 옷 안·바깥면이 몸(팔·손 포함) 표면에서 2 mm 안쪽으로 들어가는 칸은 비우고, 팔 구멍 가장자리는 톱니를 깎아 다듬은 뒤 표면 위로 다시 올린다. 멜빵 끈은 몸 밖으로 밀어내기와 다듬기를 번갈아 해서 어깨를 매끈하게 감는다. `--what clipcheck`로 확인 (11/6 수정 전: 멜빵 52 mm·보드숏 18 mm·조끼 16 mm·머리띠 5 mm 파묻힘).
- 합성 순서: 기본 → 하의 → 상의 → 머리 (`wornLayers`). 홈·치장 시착·보상 hero에 같은 합성을 쓴다.
- 칭호는 몸에 입지 않고 헤더 칩 + 메달 썸네일로만 보인다.
- 다시 렌더: 스크립트 머리말의 명령 참고. 렌더 사이에 장면 데이터를 다시 만들지 않고(`use_persistent_data`) 노이즈 제거를 GPU로 해서 RTX 4050 노트북에서 돌려보기 한 장 약 0.5초다 (예전 6초는 CPU 병목).
  `--what turn`/`motion`을 `--rows`·`--acts`로 나눠 동시에 돌리고, 중간에 멈추면 `--skip-existing`으로 이어서 만든다.
- 터치 반응 동작: 곰 glb에 들어 있는 뼈대(root·spine·head·arm·leg·ear·tail)와 동작(`wave`, `happy`)을 쓰고, 발 동동은 스크립트에서 뼈를 직접 움직여 만든다 (`pose_motion`).
  옷은 몸 표면에서 가장 가까운 곳의 뼈 가중치를 받아 뼈대에 붙인다 (`bind_to_rig`). 머리 아이템은 머리에 고정, 상의는 몸통만, 하의는 몸통 + 다리 (팔 가중치까지 받으면 팔을 들 때 조끼 자락이 부채처럼 늘어났다). `--what motion_preview`로 곰+옷을 진짜 3D로 찍어 확인한다.

## 캐릭터 움직임 (`KagomCharacter`)

터치 반응은 뼈대로 움직인 3D 동작을 렌더한 프레임을 24 fps로 재생한다 (몸 + 착용 레이어를 프레임마다 합성, 4장까지 미리 동시에 합성). 첫·끝 프레임이 기본 자세라 기본 렌더와 이어진다.
숨쉬기는 몸과 옷을 겹친 그림을 통째로 늘였다 줄인다(기준점 발끝).
참고: Duolingo 캐릭터의 대기 상태(숨쉬기·깜빡임·끄덕임을 상태 기계로 섞음).

| 언제 | 동작 |
|---|---|
| 탭 (기어 P + 대기 표정) | `TouchAct` 3종 중 바로 전과 다른 것: 손 흔들기(왼팔 들어 흔들고 고개 갸웃, 1.6초), 만세(두 팔 들고 깡충, 귀 쫑긋, 0.9초), 발 동동(왼발·오른발 번갈아 들고 몸·고개·팔이 같이 흔들림, 1.2초). 동작 중에는 웃는 눈. 돌리기 시작하면 멈춘다. 예전 2D 변형(통통·오뚝이·깡충)은 뺐다 |
| 가만히 (기어 P) | 3.2초 주기로 세로 1.2% 숨쉬기 |
| 가만히 (기어 P + 대기 표정) | 2.6~5.2초마다 눈 깜빡임 0.12초 (네 번에 한 번은 두 번). `base_<P0n>_blink.webp` = 대기 표정 + `eyes:blink` 1.0 |
| 주행 중 | 움직이지 않는다 |
