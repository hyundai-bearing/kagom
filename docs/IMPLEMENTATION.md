## 디자인에 없던 값 (가정)

- **POP-02 공개 최신본 반영 (2026-11-10)**: 원본 Kagom App을 이 날짜에 새로 복제한 `dknfqXLwkeJBHloP5qcQSG`의 Full `7:2514` / Split `64:3841`을 조회했다. 공개 본문의 보상 종류 안내·도전과제 달성 두 줄을 제거하고 아이템명 → EXP → 카곰 대사 → 버튼 순서로 표시한다. Figma 카드 크기는 Full 880×638, Split 600×650이며 너비·hero 크기는 유지하고 내용에 맞춰 높이를 줄인다. 높이 부족 시 기존 본문 스크롤 정책을 유지한다. 언박싱 이전 문구와 실제 아이템 썸네일·보상 데이터는 유지한다.

- **MNT-02 후속 수정 (2026-11-10, 사용자 승인)**: Pleos 누적 주행거리 기준 10,000 km마다 점검한다. 12개월 경과만으로 완료를 열지 않는다. 1만 km 완료 후 2만 km 미만에서는 체크리스트 대신 완료 내역·다음 점검까지 남은 거리를 표시한다. 신호 누락·비정상 값에서는 완료를 막고 확인 불가를 표시한다. 컨트롤러도 최신 거리·차종·필수 체크를 재검증하므로 연타로 다음 회차가 완료되지 않는다. 놓친 회차는 현재 도달한 구간을 한 번만 완료하며 과거 회차를 연속 처리하지 않는다. 기존 저장 키와 완료 기록은 유지한다.
- **전기차 점검 항목**: 연료/SOC 신호로 판별한 EV에는 타이어 공기압·마모, 전조등·방향지시등·브레이크등, 와이퍼·워셔액을 표시한다. 가솔린·HEV 문구와 저장 키는 유지하고 EV 체크는 별도 키를 쓴다. EV에는 엔진오일 교체 카드를 표시하지 않는다. 디버그 `--ez demo_ev true|false`로 실제 컨트롤러를 전환할 수 있다.

- **POP-02~05 승인 사항 (2026-11-10)**: Full/Split Figma 원본(POP-02 `63:3228`, `7:2514`, `64:3673`, `64:3841`; POP-03 `7:2528`, `64:3979`; POP-04 `7:2542`, `64:4135`; POP-05 `7:2433`, `7:2471`) 기준. 실제 Pleos 창은 넓을 때 1682×1210, 좁을 때 841×1210이므로 비율이 다르다. 보상·레벨업은 높이가 부족할 때 본문을 스크롤하고 버튼은 고정한다. 정비 Split 시트는 상단 최소 128 디자인 px을 남기고 전체 내용을 스크롤한다. 추가 축소는 하지 않는다.
- **팝업 상태·닫기**: 열기 560ms / 빛 걷힘 520ms / EXP 900ms 유지. 열기 수락 즉시 `opened`를 저장해 주행·Activity 재생성 후 공개 단계에서 재개한다. POP-02~04는 버튼으로만 종료하며 바깥 터치·뒤로가기는 소비한다. POP-05는 바깥 터치·뒤로가기로 닫고 끌어내리기는 지원하지 않는다. 정비 시트가 열린 동안 보상 큐는 표시·소비하지 않는다.

## 글자 크기 = Pleos Connect 글자 단계 (2026-11-10)

- **기준**: Pleos Connect Developer Guide > Designing the UI > Typography (`document.pleos.ai/en/docs/connect/guide/docs-design/foundations/typography`, 2026-11-10 확인). 폰트 Asta Sans(이미 쓰는 폰트), 실제 화면 18px 이상 권장. 크기/줄 높이: Headline 60/80 · 56/72 · 48/64, Title 40/52 · 36/44 · 32/40, Body 30/38 · 28/36 · 26/34, Label 24/28 · 20/24.

## Figma 2026-11-10 반영 (SCR-04 개편, SCR-00 Carry-over, 티어 → 레벨)

11/9 내보내기와 11/10 Figma 사본을 프레임 59개 전부 픽셀로 견줘 달라진 것만 옮겼다. POP-02~05도 바뀌었는데 그쪽은 PR #7에서 다룬다.

- **SCR-04 도전과제** (6:2085 / 7:2099): 제목 → 달성률 카드(곰 얼굴 + 퍼센트 + 바) → 필터 칩(전체·달성·미달성) → 카드 목록. 카드는 아이콘 칸 + 이름·조건·EXP, 오른쪽에 달성 날짜·시각 또는 진행 숫자·바. 보상 미리보기(?·아이템)와 머리의 "달성 n/n"·"누적 EXP" 배지는 없어졌다.
  - 이름·아이콘은 `Quest.name`·`Quest.icon`, 목록 순서(달성이 위, 최근 달성 순)와 달성률은 `Progress.listed`·`achievedPercent`.
  - 요약 카드의 곰 얼굴과 과제 아이콘은 Figma 벡터를 Android 리소스로 변환해 사용한다.
  - 달성 시각은 `AppData.questDoneAt`에 새로 적는다. 그전에 달성한 과제는 시각이 없어 "달성"만 보인다 (가정).
  - 단발형이 진행 중일 때의 모습과 필터 결과가 비었을 때의 글은 Figma에 없어 정했다 (누적형처럼 숫자·바, "아직 달성한 도전과제가 없어요" / "도전과제를 모두 달성했어요").
- **SCR-00 Carry-over** (218:4551 / 218:4672): 새 차에서 이전 카곰 기록을 찾았을 때 A "계속 함께하기" / B "새 카곰과 처음부터 시작하기"를 고른다 (`CarryOverScreen`). 고를 때까지 다른 탭·팝업은 막고, 주행 중에는 잠금 화면이다.
  - A: 칭호·아이템·EXP·방문 기록은 그대로. 주행거리 기준값은 새 차의 첫 신호로 다시 잡고, 이전 차에서 달린 거리는 `Profile.carriedKm`으로 넘긴다 (`Progress.drivenKm`). 정비 기록은 새로 시작한다 (가정: 정비는 차마다 다르다).
  - B: 기록을 SharedPreferences `archive_v2`에 보관하고 초기화 → 성향 테스트. 보관한 기록을 다시 여는 화면은 디자인에 없다.
  - **새 차를 알아채는 방법은 아직 없다.** 기록은 기기에만 저장되고 차량 식별 신호를 쓰지 않아서, 지금은 시연 훅으로만 뜬다 (시연 패널 "이전 카곰 기록 발견", `--ez demo_new_vehicle true`). 실제 조건(차량 ID, 계정 연동 등)은 정해야 한다.
- **티어 → 레벨**: 헤더 칩 글자가 "레벨 N"이 됐다 (`TierEmblem`, 높이 36·글자 16/24로 Figma 값에 맞춤). 코드 이름(`Tiers`, `TierUp`)과 팝업 안 문구는 그대로다 (팝업은 PR #7).

## 화면 전환·피드백

정차 중에만 움직이고, 주행 중(gear≠P)에는 바로 바뀐다 (`KagomMotion.ms`).

| 어디 | 움직임 |
|---|---|
| 탭 이동, 카곰 생성 직후 | 앞 화면이 옅어지고 다음 화면이 나타난다 (`KagomApp`) |
| 성향 테스트 | 다음 문항이 가는 쪽에서 밀려 들어온다 ("이전"은 반대쪽). 진행 점이 늘었다 줄어든다 |
| 스킨 결과 | 카곰이 발끝을 축으로 통 튀어 오르며 나타나고 설명이 뒤따라 올라온다 |
| 정비 시트, 치장 획득 안내 | 딤이 깔리며 Full은 오른쪽에서, Split은 아래에서 들어오고 같은 길로 나간다 |
| 치장 그리드 | 탭·페이지를 넘기면 겹쳐 넘어간다. 셀 테두리 색이 부드럽게 바뀐다 |
| 진행 바 (EXP, 도전과제, 오일) | 값이 바뀌면 새 값까지 차오른다 |
| 홈 배지 | 화면이 뜬 뒤 새로 생긴 배지만 톡 튀어나온다 |
| 보상 팝업 | 닫히거나 다음 팝업으로 넘어갈 때 옅어지며 사라진다. POP-03은 미해금 색 안개가 핀에서부터 동그랗게 걷히고 방문 도장이 찍힌다. POP-04(레벨업)는 다른 보상 모달처럼 아래에서 튀어 오르며 나타난다 (광선·월계관은 Figma 이미지라 돌리지 않는다) |

- 정비 시트 버튼(보충했어요, 오일 교체했어요, 점검 다 했어요)을 누르면 위쪽 토스트로 결과를 알린다. 점검 완료로 보상이 생겨도 시트는 그대로 있고, 보상 팝업은 시트를 닫을 때까지 뒤에서 기다린다.
- 뒤로 키: 시연 패널 → 정비 시트 → 화면 안(지도 단계, 치장 패널) → 다른 탭이면 홈. 보상 팝업은 버튼으로만 닫힌다.
- 치장에서 주행 중이면 안내 글이 "주행 중에는 돌려보기와 저장을 할 수 없어요"로 바뀐다.

## 랜드마크 지도 (SCR-05)

- Pleos FusedLocation 좌표에 현재 스킨·표정·장착 아이템을 반영한 카곰을 표시한다. 내 위치 버튼은 해당 시·군 지도로 이동한다. 위치를 확인할 수 없거나 좌표가 지도 범위 밖이면 안내를 표시한다. 좌표는 저장하지 않는다.
- 카곰은 위치점 둘레(위 → 옆 → 대각선 → 아래, 가까운 쪽부터)에서 구획 이름표·핀·핀 이름표·지도 위 글을 가리지 않는 첫 자리에 둔다. 다 막혀 있으면 가장 덜 가리는 자리다. 차가 움직이는 동안 이리저리 튀지 않게, 쓰던 자리가 새로 고른 자리만큼 비어 있으면 그대로 둔다. 차가 랜드마크에 도착해 위치점과 핀이 겹치면 핀 바깥에 둔다.
- 구획 이름표는 핀, 핀 이름표, 지도 위 글·버튼(내 위치, 방위, 안내, 위치 안내·출처)의 자리를 피하고, 옮길 자리가 없으면 숨긴다.
- 지도 아래쪽에 뜨는 것끼리 겹치지 않게: Full에서 위쪽 핀의 상세 카드가 아래에 떠 있는 동안은 왼쪽 아래 안내 글을 숨기고, Split의 정차 안내는 오른쪽 아래 위치 안내·출처 글 위에 띄운다.

- 전국 지도에서 시·도를 선택하면 그 시·도의 시·군 지도, 시·군을 선택하면 구획 지도가 열린다. 지도와 목록에서 동일하게 선택할 수 있다. 상단 경로, 뒤로 가기, 지도에서 오므리기로 이전 단계로 돌아간다.
- Full에서는 지도 오른쪽, Split에서는 Figma 기준 최대 420px 높이의 지도 아래에 지역별 해금 목록을 표시한다. 진행도는 실제 등록된 랜드마크와 방문 기록을 집계한다. 미해금은 회색, 일부 해금은 연두, 모두 해금은 초록, 선택된 구획은 점선 테두리다.
- 단계를 옮기면 떠나온 단계의 그림에서 새 단계의 그림으로 시점이 옮겨 가며 바뀐다 (0.45초, 주행 중에는 바로). 단계마다 한 번 그린 그림을 통째로 옮기고 키운다 (`SceneLayer`): 프레임마다 해안선을 새 배율로 다시 그리면 에뮬레이터에서 프레임당 70~200 ms가 걸려 끊겼다.
- 치장의 잠긴 랜드마크 보상에서 [지도에서 보기]를 누르면 그 랜드마크의 시·군 지도로 바로 들어가 구획을 고르고 상세를 띄운다 (`MapScreen(focusLandmarkId)`).
- 핀 이름표는 핀 오른쪽에 두고, 공간이 부족하면 핀 아래에 둔다. Full에서는 방문 상태와 보상 이름을 이름표에 함께 표시한다.
- 방문 상태는 미방문 / 해금 중 / 방문 완료다. 해금 중은 방문은 했지만 보상 팝업(POP-03)이 정차를 기다리는 동안이고, 보상은 팝업을 닫아야 받으므로 목록에 "획득"이라고 쓰지 않는다 (Full 목록: "해금 중 · 정차하면 … 획득"). Figma 목록 핀에는 해금 중이 없어 지도 핀(`LandmarkPin` Unlocking)과 같은 색·점으로 그렸다 (가정).
- 강릉의 1읍·7면과 시내 13개 동을 9개 구획으로 표시한다. 선택한 구획의 핀은 기존 랜드마크 위경도를 지도 경계와 같은 방식으로 투영한다. 정차 중에는 핀이나 목록에서 보상 상세를 열 수 있다. 주행 중에는 상세 대신 "기어 P에서 핀 상세를 볼 수 있어요"를 알린다 (Full: 지도 왼쪽 아래 안내 글이 그 말로 바뀐다, Split: 핀을 누르면 뜬다). 미방문 보상은 이름과 잠긴 마크를 표시한다. 랜드마크가 없는 구획은 준비 중으로 표시한다.
- 전국·시·군 경계는 기존 `assets/regions/korea_map.txt`를 사용한다. 원본 © OpenStreetMap contributors (ODbL). 생성 순서는 `fetch_korea.py` → `fetch_coast.py` → `build_korea.py`다.
- 강릉 경계는 [통계청 통계지리정보서비스(SGIS)](https://sgis.kostat.go.kr)의 공공누리 제1유형 경계를 가공한 [vuski/admdongkor 2026-10-01 데이터](https://github.com/vuski/admdongkor/tree/d5d5a821c8de6cc337d47eeca604d7af76271c9b/ver20261001)를 사용한다. 가공 데이터는 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)이다. `python tools/regions/build_gangneung.py HangJeongDong_ver20261001.geojson`으로 강릉 경계를 추출하고 단순화해 `gangneung_districts.txt`를 다시 만든다.

## 캐릭터·치장 3D 렌더 (`tools/closet3d/build_closet.py`)

곰 모델(`tools/closet3d/source/pebble_bear.glb`)과 스킨 텍스처(`tools/closet3d/source/skins/`)에 맞춰 Blender에서 치장 아이템을 절차적으로 모델링하고, 같은 카메라로 렌더한다.

| 파일 (`assets/kagom/`) | 내용 |
|---|---|
| `base_<P0n>_<표정>.webp` | 스킨 8 × 표정 7 = 56장, 614×965 (Figma pebble 렌더 크기) |
| `item_<ID>.webp` | 착용 레이어 6종. 곰은 그림자만 받는 투명 처리 → 기본 위에 그대로 겹치면 맞는다 |
| `thumb_<ID>.webp` | 아이템 6종 + 칭호 메달 3종 썸네일 320×320 |
| `turn/b_<P0n>_<단>_<nn>.webp`, `turn/i_<ID>_<단>_<nn>.webp` | 돌려보기 프레임 480×754: 고도 3단(약 9°·25°·40°) × 48방향(7.5°) |
| `motion/<동작>/b_<P0n>_<nn>.webp`, `motion/<동작>/i_<ID>_<nn>.webp` | 터치 반응 동작 프레임 640×830 (24 fps): 손 흔들기 38장, 만세 22장, 발 동동 28장 |

카메라는 하나(`Rig`)다. 곰 가운데를 축으로 yaw(조명도 같이 돈다)와 pitch(위에서 내려다보기)만 바꾸고 거리는 같아서, 단을 바꿔도 곰 크기·위치가 튀지 않는다.
base·item은 이 카메라의 0단 2번 프레임(곰 왼쪽으로 15°, `HOME_YAW`)으로 찍는다 → 홈에서 밀기 시작하면 돌려보기 프레임으로 그대로 이어진다.
동작 프레임도 같은 카메라(0단, `HOME_YAW`)인데 팔을 벌리거나 뛰면 화면 밖으로 나가서, 픽셀 크기는 같게 두고 화면만 좌우 80 px·위 76 px 넓혔다 (`MW`, `MH`). 가운데 480×754가 돌려보기 프레임과 픽셀 단위로 겹친다.

표정 = 눈·입 셰이프 키 + 소품. 몸·머리 자세는 그대로 둬서 치장 레이어가 모든 표정에 맞는다.

| 표정 | 눈·입 | 소품 |
|---|---|---|
| 대기 | 기본 미소 | – |
| 배고픔 1 | 큰 눈, 입 벌림 | 작은 침방울 |
| 배고픔 2 | 살짝 졸린 눈, 입 크게 벌림 | 침방울 |
| 배고픔 3 | 처진 눈, 찡그린 입 | 침방울 + 식은땀 |
| 얼룩 | 큰 눈, 일자 입 | 볼·배·팔 기름 얼룩 |
| 피곤함 | 반쯤 감은 눈, 일자 입 | Z Z Z |
| 아픔 | 처진 눈, 찡그린 입 | 열 홍조 + 반창고 + 식은땀 |

**돌려보기** (`KagomTurntable`, `TurnState`, `turnGestures`): 치장 미리보기, SCR-02 결과 화면, 홈.
- 좌우로 밀면 돌고(관성 있음), 위아래로 밀면 고도 단이 바뀐다 (아래로 72dp 밀 때마다 한 단 위에서 내려다본다 → 머리 위 아이템 확인).
- 프레임 사이 각도에서는 양옆 방향 두 장 × 위아래 단 두 장(최대 네 장)을 각도 비율대로 섞어 그린다 (`TurnImage`, 미리 곱한 알파끼리 더하기라 겹친 곳이 비치지 않음). 예전에는 15°마다 한 장씩 바뀌고 단도 반올림해서 끊겨 보였다.
- 치장·온보딩: 손을 떼면 그 각도에 멈추고 "정면"으로 돌아간다. 홈: 손을 떼고 0.9초 뒤 제자리로 돌아오며 표정 렌더로 바뀐다. 돌려 둔 채로 누르면 기다리지 않고 0.2초에 정면으로 돌아온 뒤 터치 반응을 한다 (동작 프레임은 정면뿐이라 돌아간 그림 위에 겹치면 잔상처럼 보인다. 0.2초는 가정).
- 프레임마다 몸 + 착용 레이어를 합성해 캐시한다. 지금 각도에서 가까운 프레임부터(같은 단 전부 → 이웃 단 ±3) 만들고 최대 40장(약 58 MB)만 든다. 홈은 처음 밀 때 만들기 시작하고 20초 동안 안 돌리면 내려 둔다.
- 주행 중(gear≠P)에는 정면 고정, 홈은 대기 표정일 때만 돌릴 수 있다 (돌려보기 프레임이 대기 얼굴뿐이다. 터치 반응은 이상 상태에서도 한다 → "캐릭터 움직임").

- 아이템: 해돋이 머리띠, 커피콩 모자, 빨간 고무 앞치마, 초보운전 안전 조끼("초보" 배지), 데님 멜빵 반바지, 강릉 서퍼 보드숏.
- 옷은 몸 안쪽 축에서 광선을 쏴 표면을 따라 만든다 (밑단이 수평, 팔·꼬리 자리는 비움).
- 몸 뚫림 방지: 옷 안·바깥면이 몸(팔·손 포함) 표면에서 2 mm 안쪽으로 들어가는 칸은 비우고, 팔 구멍 가장자리는 톱니를 깎아 다듬은 뒤 표면 위로 다시 올린다. 멜빵 끈은 몸 밖으로 밀어내기와 다듬기를 번갈아 해서 어깨를 매끈하게 감는다. `--what clipcheck`로 확인 (11/6 수정 전: 멜빵 52 mm·보드숏 18 mm·조끼 16 mm·머리띠 5 mm 파묻힘).
- 아이템 레이어의 그림자: 레이어에는 옷이 몸에 드리우는 그림자가 같이 들어가고, 그 진하기는 그림자를 받는 몸의 재질을 따라간다. 그래서 레이어(정지·돌려보기·동작)는 몸 스킨을 늘 무광 P03으로 두고 찍는다 (`LAYER_SKIN`, `render_layer`). 예전에는 돌려보기·동작 레이어를 몸 렌더가 끝난 스킨(P08 금속) 그대로 찍어서 턱 밑에 반사 무늬 같은 진한 그림자가 생겼고, 정지 화면에서 움직이거나 돌리는 순간 목이 일그러져 보였다 (`docs/verification/item-layer-shadow/`).
- 합성 순서: 기본 → 하의 → 상의 → 머리 (`wornLayers`). 홈·치장 시착·보상 hero에 같은 합성을 쓴다.
- 칭호는 몸에 입지 않고 헤더 칩 + 메달 썸네일로만 보인다.
- 다시 렌더: 스크립트 머리말의 명령 참고. 렌더 사이에 장면 데이터를 다시 만들지 않고(`use_persistent_data`) 노이즈 제거를 GPU로 해서 RTX 4050 노트북에서 돌려보기 한 장 약 0.5초다 (예전 6초는 CPU 병목).
  `--what turn`/`motion`을 `--rows`·`--acts`로 나눠 동시에 돌리고, 중간에 멈추면 `--skip-existing`으로 이어서 만든다.
- 터치 반응 동작: 곰 glb에 들어 있는 뼈대(root·spine·head·arm·leg·ear·tail)와 동작(`wave`, `happy`)을 쓰고, 발 동동은 스크립트에서 뼈를 직접 움직여 만든다 (`pose_motion`).
  옷은 몸 표면에서 가장 가까운 곳의 뼈 가중치를 받아 뼈대에 붙인다 (`bind_to_rig`). 머리 아이템은 머리에 고정, 상의는 몸통만, 하의는 몸통 + 다리 (팔 가중치까지 받으면 팔을 들 때 조끼 자락이 부채처럼 늘어났다). `--what motion_preview`로 곰+옷을 진짜 3D로 찍어 확인한다.

## 캐릭터 움직임 (`KagomCharacter`)

터치 반응은 뼈대로 움직인 3D 동작을 렌더한 프레임을 24 fps로 재생한다 (몸 + 착용 레이어를 프레임마다 합성, 4장까지 미리 동시에 합성). 첫·끝 프레임이 기본 자세라 기본 렌더와 이어진다.
숨쉬기는 몸과 옷을 겹친 그림을 통째로 늘였다 줄인다(기준점 발끝).
참고: Duolingo 캐릭터의 대기 상태(숨쉬기·깜빡임·끄덕임을 상태 기계로 섞음).

| 언제 | 동작 |
|---|---|
| 탭 (기어 P + 대기 표정) | `TouchAct` 3종 중 바로 전과 다른 것: 손 흔들기(왼팔 들어 흔들고 고개 갸웃, 1.6초), 만세(두 팔 들고 깡충, 귀 쫑긋, 0.9초), 발 동동(왼발·오른발 번갈아 들고 몸·고개·팔이 같이 흔들림, 1.2초). 동작 중에는 웃는 눈. 돌리기 시작하거나 주행을 시작하면(기어 P 아님) 멈춘다. 예전 2D 변형(통통·오뚝이·깡충)은 뺐다 |
| 탭 (기어 P + 이상 상태) | 그 표정의 몸짓을 바로 한 번, 가만히 있을 때의 2배 크기로: 배고픔 = 꼬르륵, 아픔 = 오들오들, 피곤함 = 꾸벅했다 화들짝(0.9초로 줄인 것), 얼룩 = 갸우뚱(0.7초, 좌우 3°). 표정·소품은 그대로다. 3D 동작 프레임은 대기 얼굴뿐이라 이상 상태에는 틀지 않는다 |
| 가만히 (기어 P) | 3.2초 주기로 세로 1.2% 숨쉬기 (대기·얼룩) |
| 가만히 (기어 P + 대기 표정) | 2.6~5.2초마다 눈 깜빡임 0.12초 (네 번에 한 번은 두 번). `base_<P0n>_blink.webp` = 대기 표정 + `eyes:blink` 1.0 |
| 배고픔 1~3 (기어 P) | 배가 꼬르륵: 0.5초 동안 가로·세로로 출렁이다 잦아든다. 단계가 높을수록 자주(4.2~6.4초 → 3~4.6초 → 2~3.2초), 크게(1.2% → 1.7% → 2.2%). 3단계는 숨이 느리고 얕다 (3.8초, 0.9%) |
| 아픔 (기어 P) | 오들오들: 2.2~3.6초마다 0.6초 동안 좌우 2.5dp로 잘게 떤다. 숨이 느리고 얕다 (3.6초, 0.9%) |
| 피곤함 (기어 P) | 꾸벅: 2.6~5.2초마다 1.2초에 걸쳐 2.4° 기울다 잠깐 멈추고 화들짝 돌아온다. 숨이 느리고 깊다 (4.6초, 1.8%) |
| 주행 중 | 움직이지 않는다 |

표정별 몸짓은 spec 6장 "이상 감지 시 표정에 맞는 애니메이션을 루프로 전환, 단계가 높을수록 강하게"를 표정 렌더 한 장으로 옮긴 것이다 (몸과 옷을 겹친 그림을 통째로 움직인다). 3D 표정 동작 렌더가 생기면 `IdleMotion`을 교체한다.
